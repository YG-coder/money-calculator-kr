> 작성: 2026-08-28 (rev.1)
> 대상: `src/lib/policy/currency.ts` · `src/lib/exchange.ts`

## 1. 무엇을 상수화하고 무엇을 하지 않는가

다른 정책 문서(LTV·DSR·취득세·중개보수)는 "값을 확정해 코드에 넣는" 것이 목적이었습니다.
환전은 반대입니다. **대부분의 값을 코드에 넣지 않기로 한 근거**를 남기는 문서입니다.

| 항목 | 코드에 고정? | 이유 |
|---|---|---|
| 통화 고시 단위 (1 / 100) | ✅ **고정** | 은행 고시 관행. 바뀌지 않고, 틀리면 결과가 100배 어긋난다 |
| 매매기준율 | ❌ 사용자 입력 | 하루에도 여러 번 바뀐다. 빌드 시점 값은 곧 과거 값 |
| 현찰 스프레드(환전 수수료율) | ❌ 사용자 입력 | 은행·통화·상품·채널마다 다르고 검증된 공통값이 없다 |
| 환율 우대율 | ❌ 사용자 입력 | 고객 등급·이벤트·채널에 따라 다르다 |

### 1.1 ⚠️ 당초 계획에서 바뀐 것

`CALCULATOR-EXPANSION.md` 초판의 PR 4 체크리스트에는
`src/lib/policy/currency.ts — 통화별 현찰 스프레드 기본값 + verifiedAt` 이 있었습니다.

**폐기했습니다.** 이유는 하나입니다.

> 평균값을 기본값으로 심으면, 사용자가 그 칸을 건드리지 않았을 때
> **근거 없는 수수료가 조용히 계산에 들어갑니다.**

이 프로젝트에서 반복해 온 원칙(조용한 기본값 금지)과 정면으로 어긋나므로,
스프레드는 미입력 시 **계산을 차단**하고 사유를 노출하는 쪽으로 바꿨습니다.

## 2. 통화 고시 단위 — 유일한 상수

```text
100단위 고시 : JPY(일본 엔) · IDR(인도네시아 루피아)
               VND(베트남 동) · KHR(캄보디아 리엘)
1단위 고시   : 그 외 통화
```

| 항목 | 내용 |
|---|---|
| 근거 등급 | **1차** — 국내 은행 고시환율표에 단위가 명시됨 |
| 출처 | 우리은행 고시환율(일별환율조회) · 서울외국환중개 매매기준율 고시 |
| 확인일 | 2026-08-28 |

### 2.1 왜 코드로 고정해야 하는가

엔화 고시환율 `950원`은 **1엔이 아니라 100엔** 값입니다.
사용자가 고시표의 숫자를 그대로 입력하는 구조이므로, 계산기가 단위를 모르면
결과가 **정확히 100배** 어긋납니다. 이건 "조금 부정확한 참고값"이 아니라 명백한 오답입니다.

그래서 이 값만은 사용자 입력에 맡기지 않고 `CURRENCIES` 테이블에 고정했습니다.
회귀 테스트로 `HUNDRED_UNIT_CODES` 가 정확히 네 개인지, 같은 숫자를 1단위 통화에 넣으면
정확히 100배가 되는지를 고정해 두었습니다.

### 2.2 재검증 조건

날짜에 따라 값이 낡는 항목이 아니므로 **정기 갱신 대상은 아닙니다.**
다만 고시 단위가 영구불변이라고 단정할 수는 없으므로 아래 경우에는 확인합니다.

- 통화 리디노미네이션 (예: 베트남 동 화폐개혁 논의)
- 신규 통화를 목록에 추가할 때 — **그 통화의 고시 단위를 반드시 확인**
- 은행 고시 관행 변경

## 3. 계산식

근거 등급 **1차** (KB 공식 안내 자료에서 산식과 수치 예시 확인, 2026-08-28).

```text
현찰 살 때  = 매매기준율 × (1 + 스프레드율)
현찰 팔 때  = 매매기준율 × (1 − 스프레드율)

우대율 p 적용 → 스프레드율 × (1 − p)
우대율 100%   → 매매기준율 그대로
```

검증에 쓴 원문 예시 (매매기준율 1,200원 · 스프레드 1.75%):

| 구분 | 값 |
|---|---|
| 현찰 살 때 | 1,221원 |
| 현찰 팔 때 | 1,179원 |
| 우대 50% 살 때 | 1,210.5원 |
| 우대 50% 팔 때 | 1,189.5원 |

이 네 값을 그대로 단위 테스트에 박아 두었습니다.

### 3.1 우대율은 환율이 아니라 수수료를 깎는다

가장 흔한 오해입니다. **우대율 90%는 환율을 90% 깎아주는 것이 아닙니다.**
수수료를 90% 깎아주는 것입니다.

```text
매매기준율 1,380원 · 수수료율 1.75%
  우대 0%   → 1,404.15원   (수수료 24.15원)
  우대 90%  → 1,382.415원  (수수료 2.415원)
  우대 100% → 1,380원      (수수료 0)
```

우대율이 아무리 높아도 **매매기준율보다 유리해지지 않습니다.**
이 설명은 계산기 가이드·FAQ·예시 note 세 곳에 넣었습니다.

## 4. 계산을 차단하는 조건

미확인 값을 추정하지 않는다는 원칙에 따라, 아래는 결과 대신 사유를 노출합니다.

| 조건 | 사유 문구의 요지 |
|---|---|
| 매매기준율 미입력 | 실시간 환율을 가져오지 않으므로 임의의 기본 환율을 쓰지 않는다 |
| 환전 수수료율 미입력 | 은행·통화·상품마다 달라 공통 기본값을 쓰지 않는다 |
| 현찰 환율 미입력 (현찰 모드) | 위와 동일 |
| 현찰 환율과 매매기준율의 대소가 방향과 반대 | 두 값이 뒤바뀐 입력으로 보인다 |
| 목록에 없는 통화 | 고시 단위를 알 수 없다 |

### 4.1 우대율만 기본 0%인 이유

다른 정책 계산기(LTV 방공제, DSR 전세대출)에서는 조용한 0을 금지했습니다.
환전 우대율은 **예외로 기본 0%** 를 허용했습니다.

- `0%` 는 "우대 없음"이라는 **실제로 존재하는 상태**입니다.
- 0일 때 수수료가 **최대**이므로 결과가 보수적입니다.
- 방공제는 0이면 한도를 **과대** 표시하는 방향이었지만, 우대율 0은 반대 방향입니다.

즉 조용한 기본값이 위험한 방향인지 아닌지가 갈림점이며, 여기서는 안전한 쪽입니다.

## 5. 지원하지 않는 것

- 실시간 환율 연동 (API·크롤링 모두 없음)
- 은행별 수수료율·우대율 자동 적용
- 송금 보내실 때 / 받으실 때 환율
- 여행자수표·외화수표 환율
- 카드 해외결제 환율 (Visa/Mastercard 매입 환율, 해외 이용 수수료)
- 최소 환전 금액·통화별 우대 한도 등 은행 내부 조건

이 목록은 `CURRENCY_META.unsupported` 와 화면 고지 문구에 그대로 들어가 있습니다.

## 6. 반올림 주의 (구현 시 실수한 지점)

`실질 환율`(1단위당 환율)은 100단위 통화에서 자릿수가 크게 늘어납니다.

```text
100엔당 953.325원  →  1엔당 9.53325원
```

표기를 기본 4자리로 자르면 `9.5333` 이 되어 페이지 예시(`9.53325`)와 어긋납니다.
브라우저 검증에서 잡았고, **1단위 환산 환율만 6자리로 표기**하도록 고쳤습니다.

> 같은 종류의 반올림 불일치가 LTV·실투자금에 이어 세 번째입니다.
> **파생 과정에서 단위가 바뀌는 값은 표기 자릿수를 따로 확인할 것.**

## 7. 재검증 트리거

| 시점 | 확인할 것 |
|---|---|
| 신규 통화 추가 시 | 해당 통화의 고시 단위 (1 / 100) |
| 통화 리디노미네이션 | 고시 단위 변경 여부 |
| 계산 공식 변경 | 대고객 환율 산정 방식이 바뀌는 경우 |
| 지원 범위 변경 | 송금 환율·카드 결제 환율 등을 다루게 될 때 |

시세와 은행별 스프레드를 상수화하지 않아 **정기적인 수치 갱신은 필요하지 않습니다.**
다만 통화 고시 단위, 계산 공식 또는 지원 범위가 변경될 때 재검증합니다.
